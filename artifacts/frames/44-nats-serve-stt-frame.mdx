## Problem

Slice V1 of ADR-044 (shipped in #43) landed the TTS path of `voicecli nats-serve`: framework, base adapter, heartbeat loop, CLI wiring, and TTS-specific subscriber. The STT path is the missing half of the cutover — lyra cannot migrate Machine-1 off the Unix-socket `stt-serve` daemon until `voicecli nats-serve stt` subscribes to `lyra.voice.stt.request` and replies with the ADR-044 STT schema.

Observable blocker: Roxabi/lyra#689 (slice S3 of parent lyra#658 — Machine-1 cutover runbook) explicitly names this voiceCLI sibling as a prerequisite: *"voicecli nats-serve must be merged + deployable before this cutover."* Without STT, the decoupling is 50% deployed and lyra has to keep the Unix-socket fallback for STT indefinitely.

Because the NATS adapter framework already exists (slice V1), this is a mirror-and-adapt job rather than new architecture — a subclass of `NatsAdapterBase` bound to the STT subject, plus the STT-specific fields (`text`, `language`, `duration_seconds`, per-request language-detection overrides) and a VRAM-sequencing guard that probes `stt-daemon.sock`.

## Who

- **Primary:** voiceCLI operators on `roxabituwer` who will run `voicecli nats-serve stt` alongside the TTS worker once slice V1 is deployed. They expect the same CLI shape as slice V1 (`--nats-url`, `--max-concurrent`, env-var auth) with a `--model` flag replacing `--engine`.
- **Secondary:**
  - Lyra hub (Roxabi/lyra#689 — slice S3 of parent lyra#658) — consumer of the NATS STT contract; Machine-1 cutover is blocked on this subscriber existing.
  - Future additional GPU hosts that need competing-consumer STT capacity via the `stt-workers` queue group.

## Constraints

- **Mirror slice V1 structure** — `SttNatsAdapter(NatsAdapterBase)` in `src/voicecli/nats/stt_adapter.py`, new `@nats_app.command("stt")` in `cli.py`. Reuse the adapter base, heartbeat loop, and CLI helpers verbatim; no framework changes.
- **Schema frozen by ADR-044** (landed via lyra#688, merged commit `e7a890a`) — reply fields `ok`, `text`, `language`, `duration_seconds`, `contract_version="1"`. Subject `lyra.voice.stt.request`, queue group `stt-workers`, heartbeat on `lyra.voice.stt.heartbeat` with `service: "stt_workers"`.
- **Per-request overrides** — `language_detection_threshold`, `language_detection_segments`, `language_fallback` must apply on that request only, via `STTService(cfg.model_copy(update=overrides))` per lyra's `stt_adapter_standalone.py` pattern. No mutation of adapter state across requests.
- **VRAM sequencing** — abort with exit 78 if `~/.local/share/voicecli/stt-daemon.sock` is live. Mirror of the TTS guard from slice V1, pointing at the STT daemon socket.
- **Default `--max-concurrent` = 2** (architect iter-1 note: transcription is faster than synthesis; 1 is overly conservative).
- **Additive only** — `voicecli stt-serve` (Unix-socket daemon) and its tests must remain green. No shared state; no changes to `stt-serve` lifecycle.
- **Test mirror** — `tests/nats/test_stt_adapter.py` follows the 12-case structure of `test_tts_adapter.py` from slice V1.
- **Doc update** — `docs/NATS-SERVE.md` gets a short STT section (env vars unchanged; `--model` replaces `--engine`).

## Out of Scope

- Mock engine + docker-compose E2E harness — tracked as slice V3 (#B).
- `SKILL.md` / `CLAUDE.md` polish for the new command — tracked as slice V4.
- Removing or deprecating `voicecli stt-serve` (Unix-socket daemon) — stays until lyra#689 (Machine-1 cutover) completes.
- Lyra-side consumer changes — tracked in parent Roxabi/lyra#658 and its slices (lyra#689 for Machine-1).
- Framework changes to `NatsAdapterBase`, heartbeat loop, or CLI helpers — slice V1 froze these; any drift here indicates scope creep.
