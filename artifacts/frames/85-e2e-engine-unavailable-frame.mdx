## Problem

The `e2e` CI job fails on every staging run. The TTS satellite responds with
`ok: false, error: engine_unavailable` before generating any audio. The NATS
envelope is well-formed — the failure is on the engine side, not the protocol.

Root cause unknown. Hypothesis: satellite startup / ready-signal contract drift
between docker-compose stack and satellite code.

## Who

- **Primary:** Developers — CI blocks PR merges, prevents quality-gate validation
- **Secondary:** Release workflow — cannot rely on e2e as regression guard

## Constraints

- CI staging only — local runs not affected (or untested)
- Docker-compose stack topology fixed by prior work (#44, #49, #69)
- Real engine (qwen-fast) in current stack → prefer mock for isolation
- Must pass `tests/e2e/test_nats_roundtrip.py::test_nats_roundtrip`
- Unit tests (416) pass green — only e2e affected

## Out of Scope

- NATS protocol changes (envelope is correct)
- Production satellite behavior (only CI stack)
- Performance optimization

## Complexity

**Tier: F-lite** — Clear scope (fix e2e test), single domain (CI infrastructure),
known hypothesis. Likely 4–8 files: compose stack, satellite startup, test harness,
possibly mock engine wiring.
