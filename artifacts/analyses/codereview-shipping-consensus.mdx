## Problem

14 code-review findings (3 Blockers + 4 High + 7 Medium + 5 Low) were produced
by 6 parallel review agents across a cross-repo video+voice tooling push:

- **roxabi-plugins** — 3 new skills, 1 new script, 2 updated skills, 1 updated playbook
- **voiceCLI** — 1 new script, 1 new skill, 1 updated skill (yt-clone v1.0 → v1.1)

Question: how should these findings be sequenced into PRs across the two repos?

## Panel

| α | Focus |
|---|-------|
| architect | arch soundness, maintainability, review-load economics |
| devops | CI cost, blast radius, deploy risk, rollback granularity |
| product-lead | user impact, time-to-value, review-effort ROI |

## Consensus ρ

**Two PRs per repo, scoped by concern.** Land B+H now (one PR per repo), fast-follow M (one PR per repo), leave L ad-hoc.

### PR1 breakdown

**roxabi-plugins PR1 — doc + visible-surface fixes**
- B1 — `video-analyze/SKILL.md:161` playbook link (5 → 4 levels)
- B2 — `explain/SKILL.md:35` missing opening `"` on `--compare` cell
- M6 (ride-along, doc-only) — top-level `## Flags` table in video-analyze
- M7 (ride-along, doc-only) — `VIDEO-VOICE-PLAYBOOK.md` Gaps section refresh

**voiceCLI PR1 — footguns + correctness**
- B3 — define `--start` w/o `--duration` behavior in yt-clone
- H1 — `sample_pick.py:80` trailing-silence truncation
- H2 — drop `.` and `..` from VOICECLI_DIR discovery (both voiceCLI SKILL.mds)
- H3 — `~/projects/lyra-stack` → `~/projects` (yt-clone:85, 174)
- H4 — define `--start ∧ --blind` precedence

### PR2 breakdown (fast-follow)

**roxabi-plugins PR2** — M1 allowlist · M2 fixed filename · M4 stable sort · M5 compound stop-terms
**voiceCLI PR2** — M3 ffmpeg stderr surfacing

### Rationale

1. **Natural repo boundary.** Findings split cleanly by repo; per-repo PRs match the independent release-please cadences under Convention A.
2. **Behavior vs doc separation at the repo level.** roxabi-plugins PR1 is all documentation; voiceCLI PR1 is all behavioral. Diff history stays coherent, bisect stays cheap.
3. **H1 + H2 must ship now.** Both are silent-corruption bugs (dropped audio segment · wrong-repo discovery). Architect held a veto-level ξ on letting them linger; devops confirmed H3's `|| true` already masks a VRAM-leak failure mode. Deferring violates correctness > polish.
4. **Doc ride-alongs.** M6 and M7 are zero-risk text edits in files already touched by B1/B2 — bundling them keeps PR2 small.
5. **Low = ad-hoc.** L1-L5 are taste/defense-in-depth with no user-visible impact for a solo operator. Fix when adjacent code is touched.

### Trade-offs

- **2 PRs × 2 repos = 4 PRs to land.** More ceremony than a single sweep, but gives bisectable commits for the one workflow run that's days away.
- **M5 not promoted.** Compound stop-term bypass (`AI-NATIVE` slips past `AI` filter) affects shipped output quality but not correctness; shipping with it for days until PR2 is acceptable given solo use.
- **No coordinated release.** roxabi-plugins and voiceCLI tag independently; one may ship before the other. Acceptable — they're not coupled.

Product-lead argued H1 + H2 could defer to PR2, conditional on H2 not
triggering in Mickael's current `~/projects/` layout (it doesn't today — no
adjacent voiceCLI sibling dirs). Recorded: architect's veto on shipping with
silent-corruption behavior overrode the conditional deferral.

## Implementation Notes

- **Branch naming:** `fix/codereview-pr1-blockers-highs` per repo
- **Commit style:** one commit per finding (B1, B2, B3, ...) for bisectable history; squash discouraged under Convention A anyway
- **Release-please:** PR1 fixes are `fix:` prefix → patch bump (e.g. `voicecli/v1.1.1`, `web-intel` skill patch). No breaking changes.
- **Verification:**
  - B1 — `ls` target path after fix resolves
  - B2 — render SKILL.md, confirm table integrity
  - B3/H4 — test yt-clone with `--start 30` alone and `--start 30 --blind`
  - H1 — synthetic wav ending mid-silence → confirm last segment included
  - H2 — run sample-pick from `~/projects/lyra/` → confirms VOICECLI_DIR resolves to `~/projects/voiceCLI`
  - H3 — grep for `lyra-stack` returns zero after fix
- **Skip CI concerns** — SKILL.md has no test harness; Python scripts lack tests. Manual verification per above is sufficient for personal tooling.
