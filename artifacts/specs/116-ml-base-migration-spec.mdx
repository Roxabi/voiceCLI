## Scope

This spec covers **only the voiceCLI-side migration**. The `roxabi-ml-base` repo bootstrap + image publishing is tracked in a sibling issue (to be created after this gate). voiceCLI work cannot start CI-side until the ml-base GHCR tag is published, but local Phase A/B/C iteration proceeds in parallel against a locally-built `ml-base:local` tag.

Cross-repo merge gate: voiceCLI PR must not merge to staging until `ghcr.io/roxabi/ml-base:cu128-py312-torch2.7.1` is publicly pullable.

## Context

Promoted from issue #116. No frame artifact (gap acknowledged at gate; F-lite frame backfill skipped — problem statement comes from issue body + this spec). Cross-review by devops + architect agents on 2026-04-26 surfaced 14 findings; all resolved below.

## Problem (re-baselined)

**Original premise (rejected):** "E2E pulls 5 GB torch, takes 3 min."
**Actual root cause:** E2E GHA job already does NOT install torch on the runner (commit `b3f7182` fixed that — runner installs only `pytest nats-py nkeys`). The 3-min E2E cost decomposes as:

| Phase | Time (current) | Bottleneck |
|---|---|---|
| Runner deps install | ~5 s | already optimized |
| `docker pull ghcr.io/roxabi/voicecli:staging` (×1, shared by both compose services) | ~120–150 s | **the actual bottleneck — pulls full ~7 GB image** |
| Pytest runtime | ~10–20 s | mock-engine roundtrip |
| Compose teardown | ~5 s | — |

Staging/prod build (~5 min) is dominated by Dockerfile `uv sync --frozen --extra nats` from scratch each run (no GHCR layer cache hit between runs on ephemeral GHA runners).

## Goal

1. Move torch + torchaudio + flash-attn out of voiceCLI's `pyproject.toml` core deps and into a shared base image. Result: voiceCLI image is `FROM ml-base + extras + app source`.
2. Split deps so the mock-only E2E path doesn't pull ML engines. Result: a slim mock-SUT image (≤200 MB) that compose pulls instead of the 7 GB full image.
3. Preserve current Dockerfile properties: multi-stage, non-root user, `uv sync --frozen` lockfile-driven install, healthcheck.

### Re-baselined success criteria

| Build | Current | Target | Bottleneck addressed |
|---|---|---|---|
| voiceCLI E2E (GHA, full job) | ~3 min | **<60 s** | Compose pulls slim mock-SUT (~150 MB) instead of 7 GB image |
| voiceCLI staging (no cache) | ~5 min | unchanged first run | — |
| voiceCLI staging (warm cache) | — | **<90 s** | `FROM ml-base` cached + only app layer rebuilds |
| voiceCLI prod (warm cache) | — | **<90 s** | same |

`<30 s` E2E target from the original draft is **rejected** — physically unreachable while compose still pulls *any* SUT image. <60 s with slim SUT is the credible target.

Image dedup math: voicecli-tts and voicecli-stt currently share the same `voicecli:staging` image — already deduped at registry level. Cross-project dedup with imageCLI is **deferred from success criteria** (out of scope for #116; only realized when imageCLI lands).

## Architecture

```
ghcr.io/roxabi/ml-base:cu128-py312-torch2.7.1     ← published by sibling issue
    │
    ├── voicecli:staging       ← FROM ml-base AS builder → runtime split, .[tts,stt,nats]
    └── voicecli-mock:staging  ← FROM python:3.12-slim, .[nats] only, no torch
                                   (consumed by tests/e2e/docker-compose.nats.yml)
```

## Decisions

| # | Decision | Choice | Rationale |
|---|---|---|---|
| D1 | Dep-resolution strategy | `uv sync --frozen --no-install-package torch torchaudio` into a project venv that prepends base site-packages via `.pth` | Keeps lockfile authority; avoids re-downloading torch; rejects `uv pip install --system --break-system-packages` (was a regression). Verified: uv 0.11+ supports `--no-install-package`. |
| D2 | Multi-stage | Restored. `FROM ml-base AS builder` → `FROM nvidia/cuda:12.8.1-cudnn9-runtime-ubuntu24.04 AS runtime` | Keeps build-essential / gcc / git out of runtime image. |
| D3 | Non-root user | Carry over `voicecli:1501` from current Dockerfile | Hardening parity with current. |
| D4 | E2E SUT image | New `Dockerfile.mock` published as `ghcr.io/roxabi/voicecli-mock:staging`; compose updated | Fixes the actual E2E bottleneck (SUT pull). Per architect rec, this is built fresh per push, not a separate published lifecycle — published only because compose pulls by tag. |
| D5 | `[mock]` extra | **Removed.** `Dockerfile.mock` installs `.[nats]` (core + nats client). Mock engine is gated by `VOICECLI_ENABLE_MOCK_ENGINE=1` env var at runtime. | Empty extra was semantic noise. |
| D6 | flash-attn | **Keep baked in.** Verified qwen-tts emits "Will only run the manual PyTorch version. Please install flash-attn for faster inference." → real perf path. Pin exact version in ml-base. | Empirical, not assumed. Sibling issue specifies version. |
| D7 | CUDA 12.5 → 12.8 | Approved with cuDNN ABI guard (see D8) | sm_120 (Blackwell) for M₂ dev; cu128 wheels include sm_86. Rejecting alternative "stay on 12.5" because it blocks Blackwell dev iteration. |
| D8 | cuDNN ABI risk | Phase D smoke test extended: must run `from ctranslate2 import Translator` + 1-utterance whisper inference on M₁ | `faster-whisper` ships ctranslate2 wheels linked to specific cuDNN; cuDNN 9 vs 8 is ABI-incompatible. |
| D9 | uv.lock regen audit | After dep removal, re-evaluate every `[tool.uv] override-dependencies` entry; commit lock-diff explanation | Overrides were added because of torch's transitive pulls (transformers/numpy/pandas). May no longer be needed or may be under-constrained. |
| D10 | ml-base tag pin downstream | `ARG ML_BASE_TAG=cu128-py312-torch2.7.1` (exact patch). Floating-minor `cu128-py312-torch2.7` tag is **not consumed** by voiceCLI Dockerfile. | Floating-minor would silently diverge from voiceCLI's torch version expectations on a 2.7.x ABI bump. |
| D11 | Quadlet rollout | Add NATS drain step before image swap on M₁ | 5–10 s restart window currently drops in-flight requests; drain via supervisor stop → image pull → unit reload → start. |
| D12 | Cross-repo coordination | Sibling issue created for `roxabi-ml-base` repo. voiceCLI PR explicitly blocked-by sibling until GHCR tag published. No "all-at-once" claim. | `/dev` is single-repo; gating is manual but explicit. |
| D13 | Repo + image visibility | Public repo + public image | Matches `Roxabi/.github`, `Roxabi/voiceCLI` precedent. No PAT plumbing on M₁/M₂/CI. |
| D14 | Base bump governance | Sibling issue's `roxabi-ml-base` README documents: torch version bump requires sign-off from all known consumers (voiceCLI now; imageCLI later) | Prevents YOLO base bumps from silently breaking downstream. |

## Local-first verification (mandatory)

### Phase A — `ml-base` local build & test (M₂)

Tracked in **sibling issue**, not #116. Prerequisite for Phases B/C.

### Phase B — voiceCLI prod Dockerfile against `ml-base:local` (M₂)

```bash
cd ~/projects/voiceCLI/.claude/worktrees/116-ml-base-migration
podman build --build-arg ML_BASE_TAG=local -t voicecli:local .
podman run --rm --gpus all voicecli:local voicecli --help
podman run --rm --gpus all -v ~/.voicecli:/home/voicecli/.voicecli \
  voicecli:local voicecli generate "Bonjour, ceci est un test." -e qwen-fast
```
✅ Pass: image builds, multi-stage runtime ≤8 GB, voicecli imports, qwen-fast generates, container runs as non-root.

### Phase C — slim mock SUT + compose E2E (M₂)

```bash
podman build -f Dockerfile.mock -t voicecli-mock:local .
# expect <60 s build, <200 MB image
# Patch compose to use voicecli-mock:local, run pytest tests/e2e/
podman compose -f tests/e2e/docker-compose.nats.yml up --abort-on-container-exit
```
✅ Pass: image <200 MB, compose stack starts in <30 s, E2E suite green.

### Phase D — M₁ Ampere prod-readiness (cuDNN ABI guard) — D8

# On M₁, after sibling issue publishes ml-base

podman run --rm --gpus all -v ~/.voicecli:/home/voicecli/.voicecli \

✅ Pass: torch ✓, flash_attn ✓, ctranslate2 ✓ on sm_86, whisper inference produces non-empty text on M₁ (no cuDNN ABI errors).

## Risks (post-mitigation)

| # | Risk | Mitigation | Severity |
|---|---|---|---|
| R1 | `uv sync --no-install-package torch` semantics differ on uv 0.11.x → torch reinstalled | Verify on locked uv version (0.11.7 per current Dockerfile) before #3 | 🟡 med |
| R2 | uv.lock regen surfaces dep conflicts (transformers/numpy overrides become stale or under-constrained) | D9 audit step; commit lock-diff explanation; rollback by reverting pyproject.toml + uv.lock | 🟡 med |
| R3 | ctranslate2 cuDNN 9 ABI mismatch on M₁ | D8 Phase D gate explicitly tests it before rollout | 🟡 med |
| R4 | `voicecli-mock:staging` falls behind `voicecli:staging` on app code → false-pass E2E | Both built from same source in same publish workflow; tag identically. Add CI guard: fail if only one image was built. | 🟡 med |
| R5 | Cross-repo merge ordering missed → voiceCLI staging CI red | PR #2 explicitly blocked-by sibling issue; checklist in PR description | 🟢 low |
| R6 | Quadlet swap drops in-flight NATS requests | D11 drain protocol | 🟢 low |
| R7 | Public ml-base repo exposes torch/CUDA pins | Already public info via voiceCLI Dockerfile | 🟢 accepted |

## Rollback plan

| Failure point | Rollback |
|---|---|
| uv.lock regen produces unresolvable graph | Revert pyproject.toml + uv.lock; voiceCLI PR stalls; sibling ml-base unaffected |
| `Dockerfile` (FROM ml-base) breaks Phase B | Revert Dockerfile only; pyproject changes survive |
| `voicecli-mock:staging` E2E green but real `voicecli:staging` broken on M₁ | Quadlet swap to `voicecli:staging-prev` (tag previous prod image before swap per D11) |
| ctranslate2 / cuDNN mismatch detected in Phase D | Block PR #2 merge; sibling issue must downgrade base to cuDNN 8 or pin ctranslate2 |
